# OnMyWay AI 공모전 프로젝트 소개 초안

공식 접수양식 02의 1~8번 작성란에 대응합니다. 개인정보, 동의 여부와 서명은 본인이 별도로 작성합니다. 아래에는 실제 에뮬레이터에서 확인한 고정 데이터 흐름과 아직 검증하지 않은 실제 제공자 연결을 구분했습니다. 제출 준비가 완료된 문서가 아닙니다.

앱명 / 프로젝트명: OnMyWay AI

## 1. 앱 한 줄 소개

가는 길의 할 일을 시간 안에 끝내는 차량용 AI 플래너입니다.

## 2. 기획 배경

퇴근길에 약 수령, 예약 물품 픽업, 장보기까지 처리하려면 목적지의 위치만으로는 부족합니다. 마감 시각, 현장 체류시간, 꼭 해야 할 일과 미뤄도 되는 일을 함께 고려해야 합니다. 가까운 장소를 먼저 골라도 먼저 닫는 장소를 놓치거나 최종 도착 시각을 넘길 수 있습니다.

OnMyWay AI는 여러 생활 용무를 자동차로 처리하는 운전자를 우선 대상으로 합니다. 사용자가 말한 요구를 확인 가능한 조건으로 바꾸고, 이동·대기·체류시간과 최종 도착 기한을 함께 계산합니다. 실행이 어려우면 필수 용무를 몰래 삭제하는 대신 충돌 이유와 조정 가능한 조건을 제시합니다. 실제 고객 인터뷰와 사용성 조사는 아직 수행하지 않았으며, 이 문제 가설을 초기 사용자 검증 대상으로 삼습니다.

## 3. 앱 주요 기능 및 차량 특화 요소

정차 중 용무의 필수 여부, 이용 가능 시간, 예상 체류시간과 최종 도착 기한을 확인합니다. 자연어 요구 해석과 실제 장소·도로 제공자 연결은 키 설정 후 검증할 예정입니다. 영업시간이나 서비스 제공 여부가 불명확한 후보는 확정 가능한 경로로 취급하지 않습니다.

계획기는 이동·대기·체류와 시간 창을 합산하며, 필수 용무가 불가능한 경우와 정보가 부족한 경우를 구분합니다. 현재 고정 데이터 모드에서 HTTP 계획 요청, 사용자 승인, 안내·도착 시뮬레이션, 명시적 완료와 남은 용무 재계획을 실제 네이티브 화면에서 확인했습니다. 시뮬레이션 도착만으로 용무를 완료하지 않습니다. 최종 귀가 목적지도 계획에 포함합니다.

Pleos 에뮬레이터의 실제 CarUxRestrictions를 읽고 NaviHelper 서비스 연결을 확인했습니다. Drive·30km/h에서 편집과 목적지 승인이 잠기며, 시연용 상태 설정으로 이 제한을 우회할 수 없음을 확인했습니다. 차량 상태 미확인 시에도 제한을 유지합니다. 서비스 연결은 실경로 요청 승인이나 실제 도착 검증을 뜻하지 않습니다.

## 4. 주요 사용 시나리오

현재 시연은 사용자가 명시적으로 선택하는 고정 데이터 예제입니다. 18:00 출발, 귀가 기한 19:00이며 약 수령과 세탁물 수령은 필수, 우유 구매는 선택입니다. 약 수령은 18:05 도착·10분 체류 후 18:15 완료, 세탁물은 18:20 도착·5분 체류 후 18:25 완료, 우유는 18:30 도착·5분 체류 후 18:35 완료, 집 도착은 18:40으로 계산됩니다. 장소·시간은 합성 데이터이며 AI 해석 결과나 실시간 도로 정보가 아닙니다.

실제 앱은 HTTP 서버에서 세 용무 계획을 받아 표시합니다. 사용자가 승인한 뒤 안내와 도착을 시뮬레이션해도 첫 용무는 미완료로 남습니다. 사용자가 명시적으로 완료하면 남은 두 용무를 다시 계획합니다. 이 흐름을 Pleos 에뮬레이터의 설치된 앱에서 확인하고 녹화했습니다. 실제 도로 안내와 실제 차량 운행은 검증하지 않았습니다.

## 5. 개발 계획

Kotlin 네이티브 차량 앱과 Python FastAPI 서버를 단일 저장소로 구현했습니다. 요구 구조화와 시간 제약 계산을 분리하고, 고정 데이터와 실제 제공자 모드를 명확히 구별합니다. Python 테스트 25개와 Android 단위 테스트 13개가 통과했으며 demo·live의 debug·release 빌드를 확인했습니다. v3 서명 release APK 두 종류를 Pleos Connect 2.1.0·API 34 에뮬레이터에 설치·실행했습니다.

확인한 Pleos 범위는 실제 차량 UX 제한 읽기와 내비게이션 서비스 연결입니다. 실제 경로 요청 승인·도착, OpenAI 해석과 Kakao 장소·도로 실호출은 미검증입니다. 키가 없는 live 모드에서는 503 오류를 표시하고 고정 데이터로 대체하지 않음을 확인했습니다. 키는 추후 서버 환경변수에만 설정합니다.

다음 단계는 키 설정 후 실제 제공자 응답·오류 처리, 최신 계획에 대한 승인과 실제 다음 목적지 요청, 도착·완료·최종 귀가 흐름의 통합 검증입니다. 물리 차량 운행과 사용자 조사·효과 측정은 아직 수행하지 않았습니다.

## 6. 기대효과 및 발전 가능성

기대 가치는 목적지를 반복 검색하는 수고를 줄이고, 제한된 이동시간에 할 수 있는 일과 할 수 없는 일을 출발 전에 판단하도록 돕는 것입니다. 시간 절감량과 약속 준수율은 아직 측정하지 않았으며, 비교 실험으로 확인할 계획입니다.

초기 타깃은 정기적으로 두 곳 이상의 생활 용무를 자동차로 처리하는 이용자입니다. 사용자는 첫 계획의 유용성, 필수 용무 완료 여부, 주간 재사용 여부를 중심으로 평가합니다. 유입은 공모전 시연과 차량 앱 이용자 커뮤니티를 통한 소규모 검증부터 시작합니다. 장소 정확도와 완료 흐름을 검증한 뒤 장보기·충전 중 용무·동승자 일정으로 확장할 계획입니다.

다음 수치는 사업 가설이며 실제 고객·성과가 아닙니다. 월 10,000회 대상 노출 × 상세 확인 20% × 설치 25% × 첫 계획 활성화 60%를 가정하면 첫 달 활성 사용자는 300명입니다. 다음 달 동일한 신규 활성 300명과 전월 활성 사용자 재방문율 40%를 가정하면 2개월차 MAU는 420명입니다. 실제 D30 리텐션 목표는 40%이며, 도입 후 관측값으로 가정을 수정합니다. 데이터 비용과 재사용이 확인되기 전에는 매출이나 대규모 이용자를 전제하지 않습니다.
