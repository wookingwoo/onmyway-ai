# OnMyWay AI 공모전 프로젝트 소개 초안

공식 접수양식 02의 1~8번 작성란에 대응합니다. 개인정보, 동의 여부와 서명은 본인이 별도로 작성합니다. 아래에는 실제 에뮬레이터에서 확인한 고정 데이터 흐름과 아직 검증하지 않은 실제 제공자 연결을 구분했습니다. 제출 준비가 완료된 문서가 아닙니다.

2026-11-03 설명회 대조 반영. 기존 영상·음성 증거와 이번 위치 구현·재검증을 구분합니다. 이번 Python 67개·Android 변형당 116개 테스트와 빌드·공식 AVD 위치 검증은 개발 기록에 새로 남겼습니다. 실제 제공자 실호출·새 영상 제작은 수행하지 않았습니다. [설명회 반영·보완 순서](briefing-review-ko.md)를 참조합니다.

앱명 / 프로젝트명: OnMyWay AI

## 1. 앱 한 줄 소개

귀가 마감이 있는 운전자의 퇴근길 완료 플래너입니다.

## 2. 기획 배경

퇴근길에 약 수령, 예약 물품 픽업, 장보기까지 처리하려면 목적지의 위치만으로는 부족합니다. 마감 시각, 현장 체류시간, 꼭 해야 할 일과 미뤄도 되는 일을 함께 고려해야 합니다. 가까운 장소를 먼저 골라도 먼저 닫는 장소를 놓치거나 최종 도착 시각을 넘길 수 있습니다.

OnMyWay AI는 여러 생활 용무를 자동차로 처리하는 운전자를 우선 대상으로 합니다. 사용자가 말한 요구를 확인 가능한 조건으로 바꾸고, 이동·대기·체류시간과 최종 도착 기한을 함께 계산합니다. 실행이 어려우면 필수 용무를 몰래 삭제하는 대신 충돌 이유와 조정 가능한 조건을 제시합니다. 실제 고객 인터뷰와 사용성 조사는 아직 수행하지 않았으며, 이 문제 가설을 초기 사용자 검증 대상으로 삼습니다.

## 3. 앱 주요 기능 및 차량 특화 요소

정차 중 요청 원문과 해석을 비교하고 필수·선택, 체류와 마감을 수정합니다. 모호한 수령 마감은 질문으로 확인하고, 빠진 귀가 시간은 직접 정하게 합니다. 확인 답변은 이전 요청·조건과 함께 반영하며 필수 누락과 시간 조건의 조용한 완화를 막습니다. 자연어 요구 해석과 실제 장소·도로 제공자 호출은 키 설정 후 검증할 예정입니다. 영업시간이나 서비스 제공 여부가 불명확한 후보는 확정 가능한 경로로 취급하지 않습니다.

계획기는 이동·대기·체류와 시간 창을 합산하며, 필수 용무가 불가능한 경우와 정보가 부족한 경우를 구분합니다. 현재 고정 데이터 모드에서 HTTP 계획 요청, 사용자 승인, 안내·도착 시뮬레이션, 명시적 완료와 남은 용무 재계획을 실제 네이티브 화면에서 확인했습니다. 시뮬레이션 도착만으로 용무를 완료하지 않습니다. 최종 귀가 목적지도 계획에 포함합니다.

Pleos 에뮬레이터의 실제 CarUxRestrictions를 읽고 Drive·30km/h에서 편집·승인·음성을 제한하며, 차량 상태 미확인 시에도 제한을 유지합니다. Pleos ON_DEVICE 한국어 TTS가 계산 결과를 읽는 실제 출력을 확인했습니다. NaviHelper의 내비 화면 요청과 실제 foreground 전환도 확인했으나 지도 타일 HTTP 401로 지도는 빈 화면이었습니다. 화면 연결은 실경로 요청 수락이나 실제 도착 검증을 뜻하지 않습니다.

## 4. 주요 사용 시나리오

현재 시연은 사용자가 명시적으로 선택하는 고정 데이터 예제입니다. 18:00 출발, 귀가 기한 19:00이며 약 수령과 세탁물 수령은 필수, 우유 구매는 선택입니다. 약 수령은 18:05 도착·10분 체류 후 18:15 완료, 세탁물은 18:20 도착·5분 체류 후 18:25 완료, 우유는 18:30 도착·5분 체류 후 18:35 완료, 집 도착은 18:40으로 계산됩니다. 장소·시간은 합성 데이터이며 AI 해석 결과나 실시간 도로 정보가 아닙니다.

현재 시연 영상은 한 사람의 퇴근길을 따라갑니다. 독립 선택한 저장 요청에 세탁물 18:30 수령 완료·19:00 귀가·정확한 세탁소를 포함합니다. 실제 Pleos 음성이 첫 계획을 설명한 뒤 준비된 조건 변경 문장으로 약국 체류를 10분에서 30분으로 바꾸면 세탁소 우선 방문과 선택 우유 제외, 18:53 귀가 예상으로 바뀝니다. 필수 볼일과 귀가 마감은 유지합니다. 실제 앱은 HTTP 서버의 계산 결과를 받고 Pleos ON_DEVICE 음성으로 읽습니다. 명시적 출발 문장만 현재 계획을 승인하며, 도착과 완료를 구분하고 두 필수 볼일을 각각 완료한 뒤 귀가를 별도로 승인합니다. 실제 AVD Drive 제한도 포함합니다. 사용자 대사는 저장 문장과 오프라인 제작 음성이며 실제 STT 성공이 아닙니다. 장소·도로·내비 도착은 예시·모의이고 자동 교통 지연 감지나 실제 차량 운행 결과가 아닙니다. 18:20 불가능·18:31 조정 흐름은 별도 보조 예시입니다.

## 5. 개발 계획

Kotlin 네이티브 차량 앱과 Python FastAPI 서버를 단일 저장소로 구현했습니다. 요구 구조화와 시간 제약 계산을 분리하고, 고정 데이터와 실제 제공자 모드를 명확히 구별합니다. 2026-10-26 개발 기록에는 Python 테스트 67개, Android 단위 테스트 변형당 106개, demo·live debug·release 빌드와 release lint-vital 통과가 남아 있습니다. 로컬 서명 APK와 공식 Pleos Connect 2.1.0·API 34의 모의 여정·Drive 제한 검증도 기록되어 있습니다. 이 수치는 과거 기록입니다. 2026-11-03 위치 설정 추가 후 Python 67개·Android 변형당 116개, demo/live debug·unsigned release 빌드와 debug lint를 다시 확인했습니다. 사용자 효과 지표는 아닙니다.

SDK는 STT 3.3.1·TTS 3.3.1 ON_DEVICE·NaviHelper 3.0.5를 사용하고 차량 제한은 Android Car API로 읽습니다. STT 초기화·듣기·취소, 실제 한국어 TTS 출력과 내비 화면 전환을 확인했습니다. 최종 한국어 STT, 지도 표시·실제 경로 수락·도착, OpenAI 해석과 Kakao 장소·도로 실호출은 미검증입니다. 키가 없으면 오류를 표시하고 고정 데이터로 대체하지 않습니다. 키는 추후 서버 환경변수에만 설정합니다. FusedLocation 1.1.3을 추가해 차량의 최신 위치로 출발지를 정하고, 집을 명시 저장하거나 장소 검색 결과에서 선택하는 설정을 구현했습니다. 공식 AVD에서 실제 SDK 위치 수신·확인 저장, 권한 거부 후 집 유지와 Drive/30 시 확인 창 닫힘을 검증했습니다. 오래된 위치·출처 없는 예전 좌표·이전 일정의 완료 장소는 새 출발 위치로 쓰지 않습니다. 집 근처 검색은 임의 주거 주소 변환이 아니며 실제 제공자 검증은 남아 있습니다. Vehicle SDK는 미사용입니다.

지정한 픽업 장소 고정과 이용 가능 시간·확인 근거 입력, 계산·검토 중 경과시간을 반영한 승인, 내비 요청 만료·재연결과 완료 후 자동 동선 갱신을 추가했습니다. 정보가 미확인인 시간 연장 제안은 조건부임을 표시하며 실행 가능으로 확정하지 않습니다. 다음 단계는 키 설정 후 실제 제공자 응답·오류 처리, 최신 계획에 대한 승인과 실제 다음 목적지 요청, 도착·완료·최종 귀가 흐름의 통합 검증입니다. 물리 차량 운행과 사용자 조사·효과 측정은 아직 수행하지 않았습니다.

설명회 안내에 따라 공모전 시연은 공식 에뮬레이터·버추얼 콘솔로 준비하고 PT 전까지 핵심 앱 검증을 완료하는 계획입니다. 2027년 2월 전시 준비를 추가 기능 개발 기간으로 잡지 않습니다. 생성형 AI 보조 사용과 별개로 참가자가 구조·계산·승인·실패 처리 로직을 직접 설명할 수 있도록 기술 Q&A를 준비합니다.

## 6. 기대효과 및 발전 가능성

기대 가치는 목적지를 반복 검색하는 수고를 줄이고, 제한된 이동시간에 할 수 있는 일과 할 수 없는 일을 출발 전에 판단하도록 돕는 것입니다. 시간 절감량과 약속 준수율은 아직 측정하지 않았으며, 비교 실험으로 확인할 계획입니다.

초기 타깃은 정기적으로 두 곳 이상의 생활 용무를 자동차로 처리하는 이용자입니다. 사용자는 첫 계획의 유용성, 필수 용무 완료 여부, 주간 재사용 여부를 중심으로 평가합니다. 유입은 공모전 시연과 차량 앱 이용자 커뮤니티를 통한 소규모 검증부터 시작합니다. 장소 정확도와 완료 흐름을 검증한 뒤 장보기·충전 중 용무·동승자 일정으로 확장할 계획입니다.

다음은 실적이 아닌 작은 파일럿의 계산 가설입니다. 월 대상 도달 200명 × 설치 50% × 첫 계획 활성 60%이면 신규 활성 60명입니다. 월별 재사용 40%와 동일 신규 유입을 가정하면 MAU는 1개월차 60명, 2개월차 84명, 3개월차 약 94명입니다. 월 재사용은 D7·D30 코호트 리텐션과 별도로 측정해야 합니다. 사용자 승인 후 과제 관찰과 2주 파일럿에서 필수 완료·재사용·오류·지불 의사를 검증할 계획이며 아직 모집하지 않았습니다. 과금·제휴·입점·매출은 확정하지 않았습니다. 상세 가정과 출시 조건은 contest-strategy-ko.md를 참조합니다.

## 7. 참고자료

기존 Pleos Connect 2.1.0·API 34 검증 기록의 로컬 자료 경로이며 외부 공개 링크가 아닙니다. 이번 debug·unsigned release 빌드는 로컬 출력에 있으며, 과거 서명 제출 APK·영상·공식 문서는 재생성·재검수하지 않았습니다. 예전 DOCX·PPTX·ZIP·HTML 발표는 최신 본문과 일치하도록 재생성·검수한 뒤 제출해야 합니다.

- 현재 시연 영상 164.355542초: artifacts/evidence/spoken-plan/OnMyWay_AI_spoken_demo.mp4. 실제 Pleos ON_DEVICE 한국어 계획 음성, 오프라인 준비 사용자 대사, 같은 1배속 구간의 화면·음성과 편집 자막입니다. 전체 Pleos 화면·예시/모의·대기 축약 고지를 포함합니다. 실제 최종 ASR·제공자·내비 성공의 증거는 아닙니다. 이전 183.3초 story-demo와 107.667초 intent-demo는 과거 자료입니다.
- 서명 release APK: apk/OnMyWay_AI_demo_release.apk 및 apk/OnMyWay_AI_live_release.apk. SHA-256은 artifacts/submission/apk-checksums.txt 참조.
- 현재 영상 검증 기록: artifacts/evidence/spoken-plan/media-verification.json. 원고: docs/submission/spoken-demo-ko.md. 재현: scripts/SPOKEN_DEMO.md. 실제 출력·화면 근거: docs/screenshots/spoken-plan/README.md. 후속 내비 화면 호출과 빈 지도 한계: docs/screenshots/navigation-handoff/README.md. 영상은 후속 내비 변경 전 녹화이므로 최종 APK와 다시 대조해야 합니다.
- 위치 설정의 실제 SDK 수신·집 저장·권한 거부·Drive 차단 근거: docs/screenshots/location-setup/README.md. 현재 키 설정 후 통합 검증 절차: docs/location-setup.md.

실제 AI·장소·도로 호출과 실제 SDK 경로 요청 승인·도착은 미검증입니다. 최종 공유 전 영상·첨부·저장소의 계정명과 개인정보 노출을 점검합니다.
