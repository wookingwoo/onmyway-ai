# OnMyWay AI 발표와 시연 초안

## 90초 소개

퇴근길에 약을 받고 예약 물품을 찾은 뒤 약속 시간까지 집에 가야 한다고 생각해 보겠습니다. 가장 가까운 장소부터 방문하면 될까요. 이동시간이 짧아도 약국이 먼저 닫거나 픽업 대기 때문에 약속을 놓칠 수 있습니다.

OnMyWay AI는 가는 길의 할 일을 시간 안에 끝내는 차량용 AI 플래너입니다. 사용자가 말한 용무를 필수와 선택, 이용 가능 시간, 체류시간으로 정리하고 직접 확인하게 합니다. AI가 요구를 해석한 뒤, 계산 로직이 이동·대기·체류와 최종 도착 기한을 함께 검토합니다.

계획이 가능하면 방문 순서와 예상 완료 시각을 제시합니다. 불가능하면 필수 용무를 삭제하지 않고 이유를 설명합니다. 영업시간이나 서비스가 불명확하면 확인이 필요하다고 말합니다. 사용자가 승인한 다음 방문지만 차량 내비게이션으로 연결하고, 도착 후 실제 용무가 끝났는지 확인한 뒤 다시 계획하는 흐름을 개발합니다.

현재 녹화한 시연은 고정 데이터로 세 용무를 계획하고, 사용자가 승인한 뒤 안내·도착을 시뮬레이션하고, 명시적으로 첫 용무를 완료해 남은 두 용무를 다시 계획하는 흐름입니다. 실제 Pleos 에뮬레이터에서 동작하며 실제 AI 해석·실경로 안내는 아직 검증하지 않았습니다. 실제 차량 UX 제한 읽기와 내비게이션 서비스 연결, Drive·30km/h에서 편집·승인이 잠기는 동작은 별도로 확인했습니다.

## 5분 발표 구성

1. 0:00~0:35 문제: 가까운 장소의 순서만으로는 마감과 체류를 충족하지 못하는 구체적인 퇴근길.
2. 0:35~1:10 해결: 입력에서 완료까지 이어지는 흐름과 필수·선택 용무 구분.
3. 1:10~3:10 시연: 고정 데이터 선택 → 시간표 → 승인 → 안내·도착 시뮬레이션 → 미완료 유지 → 명시적 완료 → 남은 두 용무 재계획.
4. 3:10~3:45 신뢰성: 불가능과 정보 부족 구분, 도착과 완료 분리, 주행 중 입력 제한.
5. 3:45~4:20 구현: Kotlin 차량 앱과 FastAPI, Python 25개·Android 13개 테스트 통과, 서명 APK 실행, 실제 차량 UX 제한과 서비스 연결 범위. 실호출·실경로 검증은 남은 과제로 제시.
6. 4:20~5:00 검증과 확장: 현재 검증 범위, 사용자 검증 계획, 사업 가설 300명에서 420명 MAU 계산.

각 슬라이드에는 하나의 판단 근거를 둡니다. 실행을 확인하지 않은 화면에는 “설계 예시” 또는 “고정 데이터 시연”이라고 표시합니다. 수상·입점·채용을 보장하는 문구는 사용하지 않습니다.

## 녹화 전제

확보한 영상은 `artifacts/evidence/OnMyWay_AI_Pleos_fixture_demo.mp4`, 길이 47.206초입니다. Pleos Connect 2.1.0·API 34 에뮬레이터의 실제 앱 화면 녹화이며, 시연 데이터와 안내·도착은 합성·시뮬레이션입니다. 공개 전 고정 데이터 고지 자막이 전체 길이에서 보이는지와 개인정보 노출을 최종 확인합니다. 아래 2분 30초 대본은 추가 녹화용 제안이며 현재 47초 영상의 내용·길이로 주장하지 않습니다.

## 숫자를 확인할 예제

현재 고정 데이터 예제는 18:00 출발, 19:00 귀가 기한입니다. 약 수령은 필수로 18:05 도착·체류 10분·18:15 완료, 세탁물 수령은 필수로 18:20 도착·체류 5분·18:25 완료, 우유 구매는 선택으로 18:30 도착·체류 5분·18:35 완료, 집 도착은 18:40입니다. 네 이동 구간은 각각 5분이고 이 예제의 대기는 0분이며, 최종 여유시간은 20분입니다. 실제 영업·도로 정보가 아닙니다.

현재 녹화는 첫 용무의 명시적 완료와 남은 두 용무 재계획까지 보여줍니다. 추가 영상의 불가능·정보 부족 사례는 실제 화면 결과와 맞는지 확인한 뒤 녹화하며, 현재 영상에 포함됐다고 주장하지 않습니다.

## 발표자가 준비할 질문

- “왜 차량 앱인가?” 현재 이동 맥락과 다음 방문지 안내, 정차 중 확인·완료 흐름을 연결한다. 실제 차량 데이터 연동은 검증된 범위만 설명한다.
- “AI가 시간표를 지어내지 않나?” AI는 요구를 구조화하고, 시간 계산은 별도 로직이 수행한다. 출처가 없는 시간은 검증된 값으로 쓰지 않는다.
- “기존 내비게이션과 무엇이 다른가?” 본 프로젝트가 해결하려는 단위는 목적지가 아니라 마감과 체류가 있는 용무의 완료다. 다른 제품의 미지원 기능을 조사 없이 단정하지 않는다.
- “이용자와 효과는 검증됐나?” 현재 이용자 수·절감 효과·인터뷰 결과는 없다. 활성·완료·재방문 지표로 검증할 계획이다.
- “현재 어디까지 동작하나?” 실제 Pleos 에뮬레이터에서 서명 release APK 실행, HTTP 고정 데이터 계획·승인·완료·재계획, 차량 UX 제한과 내비게이션 서비스 연결을 확인했다. OpenAI·Kakao 실호출과 실제 SDK 경로 승인·도착은 미검증이다.
