# OnMyWay AI 데모 진행 가이드

## 보여 줄 가치

퇴근길에 약을 사고, 세탁물을 찾고, 시간이 되면 우유까지 사서 정해진
시간에 집에 가는 상황입니다. 할 일의 우선순위와 시간을 사용자가 확인하고,
조건이 맞지 않으면 조정한 뒤 다음 목적지를 승인합니다.

AI의 역할은 자연어 요청을 필수·선택·체류·마감 조건으로 정리하고 모호한
부분을 질문하는 것입니다. 이동 순서와 실행 가능성은 별도 계획 엔진이
이동·영업 대기·체류·귀가 구간을 계산해 판단합니다. 상세 설명은 이 계산의
결과를 사용합니다. 모르는 영업시간이나 서비스 가능 여부를 만들지 않습니다.

**이번 키 없는 시연은 준비된 문장·해석과 예시 데이터를 사용합니다.** 실제
STT나 LLM 해석 결과라고 설명하지 않습니다. 실제 SDK 음성 입력과 서버의
LLM 연결 경로는 별도로 구현되어 있습니다. 키는 나중에 서버에서 설정합니다.

## 시작 준비

1. 이 프로젝트의 공식 `OnMyWay_Pleos` AVD를 Android Studio에서 실행합니다.
   실행 중인 기기는 `adb devices`로 확인합니다. 기본 시연 기기는
   `emulator-5556`입니다. 화면은 Android Studio의 Running Devices에서 봅니다.
2. Virtual Console에서 **Park / 0 km/h**인지 확인합니다. 실제 차량에서 시연하지
   않습니다. 음성과 복잡한 입력은 정차 중에만 사용합니다.
3. 저장소 루트 PowerShell에서 실행합니다.

   ```powershell
   .\scripts\start-demo.ps1 -Serial emulator-5556
   ```

   로컬 API를 확인하거나 시작하고 최신 로컬 서명 demo APK를 업데이트 설치한
   뒤 앱을 엽니다. 기존 앱 데이터는 지우지 않습니다. APK와 개발 도구가 없는
   새 PC의 준비 방법은 `../README.md`와 `../apps/automotive/README.md`를 따릅니다.
4. 이전 일정이 남아 있으면 **설정 → 새 일정 시작 → 새로 시작**을 선택합니다.
   시연 기기에서는 예시 일정만 초기화합니다.

예시는 재현을 위해 **2026년 10월 23일 18:00 출발**로 고정되어 있습니다.
오늘의 실제 장소·교통·영업시간 추천이 아닙니다. 예시 기본 위치는 수동 설정이
필요하지 않습니다. 앱을 다시 열거나 테마를 바꾸면 모의 안내를 다시 명시적으로
켜야 할 수 있습니다. **모의 안내 켜기**를 선택한 후 계속합니다.

## 주 시나리오: 약 3분

| 화면에서 할 일 | 설명할 핵심 |
| --- | --- |
| **질문과 답변 체험 · 예시 해석** | “퇴근길 약 구매와 세탁물 수령은 필수이고, 우유는 시간이 되면 사는 상황입니다. 준비된 예시로 흐름을 보여 드리겠습니다.” |
| 요청 원문·필수 2개·선택 1개 확인 | “말한 내용을 검토 가능한 조건으로 정리합니다. 사용자가 수정할 수 있습니다.” |
| **질문에 답하기 → 18:30 전 수령 완료** | “‘6시 반 전’이 도착인지 수령 완료인지 확인합니다. 사용자 답을 받기 전에는 계획을 계산하지 않습니다.” |
| **귀가 시간 정하기 → 19:00 확인 → 적용** | “귀가 시간을 말하지 않았으므로 임의로 채우지 않고 직접 정하게 합니다.” |
| **동선 확인하기 → 계획 근거 자세히** | “예시에서는 18:40 귀가, 마감까지 여유 20분입니다. 귀가 구간을 포함한 이동과 체류 시간을 계산합니다.” |
| **이곳으로 안내 → 목적지 승인** | “검토한 최신 계획의 다음 목적지를 직접 승인합니다. 여기서는 모의 안내입니다.” |
| **도착 체험 · 모의 이벤트 → 할 일 완료 → 완료했어요** | “도착과 할 일 완료를 구분합니다. 약 구매를 실제로 마쳤다고 확인한 뒤 남은 일정만 다시 계산합니다.” |
| **자동 갱신된 다음 동선 확인**, 같은 방식으로 세탁물·우유 완료 | “완료한 장소를 다시 방문하지 않고 남은 동선을 자동으로 갱신합니다. 다음 목적지는 새로 승인합니다.” |
| **집으로 안내 → 목적지 승인 → 도착 체험 · 모의 이벤트** | “마지막 귀가도 별도로 승인하고, 집 도착까지 흐름을 끝냅니다.” |

차량 화면의 하단 버튼이 다음 행동 하나를 안내합니다. 원문·답변과 전체 근거는
필요할 때 펼쳐 봅니다. 세부 항목 수정은 정차 중 **수정** 버튼을 사용합니다.

## 추가 시나리오: 시간이 부족한 경우

2026-10-25 추가 흐름: **마감·미확인 정보 체험 · 예시**를 독립적으로 선택하면
미확인 영업·서비스 정보가 있는 합성 사례를 시작합니다. **동선 확인하기 → 시간
조정 제안 보기**에서 11분 연장을 조건부 예상으로 표시합니다. 변경을 승인해도
가능 여부 미확인과 여유 0분 경고는 유지됩니다. 실제 제공자 오류가 이 예시를
자동 선택하는 일은 없습니다.

정확한 방문 장소 확인은 **수정 → 방문 장소 선택 → 데모 세탁소**로 체험합니다.
고정한 점포가 검토 화면과 남은 동선에 유지됩니다. 실제 모드의 장소 검색과
이용 시간·근거 입력은 서버 키 설정 이후 별도로 검증해야 합니다.

1. 새 일정을 시작하고 질문·답변 예시를 다시 선택합니다.
2. 세탁물 수령은 **18:30 전 수령 완료**로 답하고, 귀가는 **18:20**으로 정합니다.
3. 동선을 확인하면 필수 일정과 마감 조건을 함께 지킬 수 없음을 표시합니다.
4. **시간 조정 제안 보기**에서 11분 연장, **18:31** 귀가를 확인합니다. **유지**를 누르면
   기존 마감이 유지됩니다. **바꾸고 재계산**을 선택해야 새 조건으로 계산합니다.
5. 필수 일정이 남아 있는지, 우유가 이번 동선에 포함되지 않았는지, 원문 확인
   화면에도 승인한 귀가 마감이 반영되었는지 확인합니다.

설명: “필수 일을 조용히 빼지 않습니다. 지킬 수 없는 조건을 알려 주고, 사용자가
시간 변경을 승인한 뒤 계산합니다. 선택 항목이 빠졌다는 사실도 보입니다.”

## 주행 잠금과 야간 화면

- 격리된 AVD의 Virtual Console에서만 Drive / 30 km/h를 설정합니다. 질문이나
  수정 창이 닫히거나 차량 OS가 앱을 차단하고, 조작할 수 없는지 확인합니다.
  확인 후 반드시 Park / 0으로 복원합니다.
- 시스템 야간 모드에서 같은 흐름을 확인합니다. 주간·야간 모두 Pleos 주변
  화면과 어울리는 중립 색상, 큰 버튼과 명확한 글자 대비를 유지합니다.

## 재현 검사

```powershell
.\.venv\Scripts\python.exe scripts/smoke-intent.py --adb .tools/android-sdk/platform-tools/adb.exe --serial emulator-5556
```

스크립트는 격리된 공식 AVD에서만 실행하고, 예시 일정만 초기화합니다. 주 시나리오,
취소·재시작·테마 복원과 촉박한 마감 조정을 검사합니다. 실제 주행 잠금은
`--mode lock-ready` 후 `scripts/smoke-pleos-lock.py`로 별도 검사합니다.

## 복구와 제한

최신 실제 앱 영상은 로컬 `artifacts/evidence/intent-demo/OnMyWay_AI_intent_demo.mp4`
(107.667초, 1920×1080, 무음)입니다. 정상·질문 답변·세 용무 완료·별도 귀가,
촉박한 마감 조정, 실제 Drive 잠금을 담았습니다. 준비된 예시·모의 안내와
실제 STT·LLM·실경로 미검증 고지를 상시 표시하고 2배속임을 밝힙니다.
검증 내역은 같은 폴더 `media-verification.json`입니다.

```powershell
.\.venv\Scripts\python.exe scripts/record-intent-demo.py --adb .tools/android-sdk/platform-tools/adb.exe --serial emulator-5556
.\.venv\Scripts\python.exe scripts/build-pitch.py
```

녹화에는 PATH의 ffmpeg·ffprobe와 Windows 맑은 고딕이 필요합니다. 격리된 공식
AVD의 예시 일정만 사용합니다. 새 녹화 후 장면·고지·전체 재생을 다시 확인합니다.
발표 파일은 `artifacts/pitch/current/index.html`, 대본·예상 질문은
`submission/pitch-and-demo-ko.md`입니다. 이전 영상·DOCX·PPTX·ZIP은 최신 자료로
사용하지 않습니다.

- 서버 연결 오류: `start-demo.ps1`을 다시 실행하고 서버 주소가
  `http://10.0.2.2:8000`인지 정차 중 고급 설정에서 확인합니다. 로컬 API는
  `http://127.0.0.1:8000/health`로 확인합니다. 실패한 실제 호출을 예시로 바꾸지 않습니다.
- 키 없는 일반 입력은 실제 LLM 해석을 실행할 수 없습니다. 시연에서는 별도의
  예시 버튼을 선택합니다. 이후 ignored `.env`에 제공자 키와 모델을 설정하고
  API를 재시작한 뒤 실제 제공자 검증을 수행합니다. 키를 APK에 넣지 않습니다.
- 실제 한국어 최종 STT, 외부 장소·교통 호출, 실제 내비 요청 수락·도착과 물리
  차량 사용성은 별도 검증 대상입니다. 예시의 성공으로 이들을 검증했다고 하지 않습니다.
- 사용 시간 절감, 실제 사용자 수, 수상 성과는 측정·확인하지 않았습니다.
- 최신 검증 결과와 한계는 `progress.md`에 기록합니다. APK·원본 로그는 로컬에
  보관하고 승인된 실제 스크린샷만 Git에 저장합니다.
