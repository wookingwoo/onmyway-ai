# OnMyWay AI Implementation Plan

> **For agentic workers:** Execute using superpowers:executing-plans and independent parallel work where authorized. Track actual verification in docs/progress.md.

**Goal:** Deliver a working native vehicle errand planner and a reviewable contest package quickly.

**Architecture:** A native Kotlin app calls one stateless FastAPI service. An LLM extracts editable requirements; a deterministic exhaustive small-route solver checks times. Live providers and labelled fixtures are distinct. Only the native app invokes Pleos navigation after approval.

**Tech Stack:** Kotlin, Android/Compose where available, Python 3.13, FastAPI, Pydantic, HTTPX, unittest/pytest, Gradle, GitHub Actions.

**Spec:** docs/spec.md; user master scope attachment dated 2026-10-23.

## Global Constraints

- Android minimum API 28, Pleos NaviHelper 3.0.5; check current SDK signatures before compiling.
- API secrets remain on server; user configures credentials later.
- Never report fixture results as live or SDK connection as route acceptance.
- Do not publish, grant account access, sign legal consent or submit the entry.

## Review Focus

- A mandatory errand without a candidate must be infeasible or unverified.
- Finishing after closing must fail even when arrival was before closing.
- Unknown hours or missing travel edges cannot be verified feasible.
- A stale HTTP response must not overwrite an edited plan.
- A destination arrival must not automatically complete an errand.

### Task 1: API and planner

**Files:** services/api/onmyway/{models,planner,providers,main}.py; services/api/tests/*; services/api/pyproject.toml.

**Interfaces:** POST /v1/parse accepts text and reference_time; POST /v1/plan accepts structured errands, origin/home, departure and arrival deadline. GET /health exposes configured provider booleans without secrets. GET /v1/demo returns a labelled fixture request.

- [ ] Write failing behavior tests for mandatory/optional tasks, dwell, closing, missing data, opening wait, same-day deadlines and deterministic selection.
- [ ] Implement pure bounded exhaustive solver with evidence/status and alternatives.
- [ ] Implement typed API, explicit fixtures, environment-configured OpenAI and Kakao adapters with mocked HTTP contract/error tests; no silent live fallback.
- [ ] Run full Python suite and HTTP smoke test. Commit verified backend changes.
